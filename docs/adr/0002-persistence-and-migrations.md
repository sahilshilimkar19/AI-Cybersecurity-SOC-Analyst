# ADR 0002 — Persistence layer and migrations

- **Status:** Accepted
- **Sprint:** Sprint 2 — Database + Models
- **Deciders:** Lead Engineer

## Context

Sprint 2 implements the domain contracts and the persistence layer. The governing documents
fix the datastore (PostgreSQL + pgvector) and the language (Python) but leave the ORM,
migration tooling, concurrency model, and enum/object-storage strategy to implementation.
These are decided once here, within the architecture's constraints (EDS §6, §3.9, §3.13).

## Decision

1. **SQLAlchemy 2.0** as the ORM, using the typed `Mapped[...]` / `mapped_column(...)` style.
   Domain contracts (Pydantic) live in `models/` and are kept **separate** from the ORM in
   `backend/db/`; ORM rows convert to contracts via `from_attributes`. The backend is the sole
   write boundary (invariant #7).
2. **Synchronous** SQLAlchemy + **psycopg 3** for the data layer this sprint — not async.
   *Rationale:* materially simpler and lower-risk to implement and test correctly. The async
   API/streaming layer arrives in later sprints and does not change these domain contracts;
   sync sessions can run under an async framework via a threadpool if needed.
3. **Alembic** for migrations. The initial schema is autogenerated from the models and verified
   to **upgrade and downgrade reversibly**, with `alembic check` reporting no model drift.
4. **Enums stored as `VARCHAR` + `CHECK`** (`native_enum=False`) holding the enum's **string
   value**. *Rationale:* native PostgreSQL `ENUM` *types* are not dropped by `DROP TABLE`, so
   they leak and break re-`upgrade` after a `downgrade`. Non-native enums make migrations clean
   in both directions while preserving DB-level validation and matching `models/`.
5. **Identity & lifecycle:** client-generated `uuid4` primary keys; timezone-aware
   `created_at`/`updated_at`; `deleted_at` soft delete where the entity supports it (not on
   immutable evidence/audit); integer `version` columns where the spec requires versioning.
6. **Object storage:** an `ObjectStore` `Protocol` with an in-memory implementation (tests) and
   a MinIO / S3 implementation (deployments) for immutable raw evidence referenced by
   `log_events.raw_ref`.
7. **Audit trail:** append-only, with a SHA-256 content **signature** for tamper-evidence.
   Cryptographic signing / hash-chaining is hardened in the Security sprint.
8. **No `pgvector` columns yet** — the vector knowledge index belongs to the RAG sprint.

## Consequences

- **Positive:** clean, reversible migrations; strong typing end-to-end; a clear separation
  between domain contracts and persistence; DB-level enum validation; testable object storage.
- **Trade-offs:** the data layer is synchronous for now (revisited if/when a measured need for
  async data access arises); the MinIO implementation is not exercised in CI (requires live
  object storage) — the in-memory implementation and the `Protocol` are tested instead.
- **Testing:** ORM metadata, domain contracts, and object storage run without a database;
  repository and enum round-trip tests run against a real PostgreSQL (a service in CI; skipped
  locally when no database is reachable).
